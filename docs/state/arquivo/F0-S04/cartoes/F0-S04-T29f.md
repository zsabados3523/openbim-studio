## Problema
Na medição oficial de memória na placa (2026-10-21) o JSON do `prototypes/viewport_qrhi/medir.py` não traz `reinicios`, `registro_reinicio` nem `desenho.software`. Não dá para provar, só pelo JSON da placa, que o reinício planejado disparou (bloco, fonte, tempo perdido) nem que o desenho foi feito pela placa.
## Objetivo
`medir.py` passa a gravar no JSON (última linha) os campos que o carregador já tem no resumo: `reinicios`, `registro_reinicio` (bloco, fonte, tempo perdido, decisão) e `desenho` (`info` do OpenGL e `software`), no mesmo formato que `sonda_ensaio_t33.py` já usa. Nenhum número, meta ou limite muda; nenhum campo existente muda de nome.
## Aceite
1. O JSON de uma abertura com reinício (gancho `OBIM_TESTE_CRESCER_MB`, nos testes T29b) traz os campos com os valores do carregador.
2. Os testes que leem o JSON do `medir.py` passam sem edição; nenhum teste de oráculo editado.
3. `--auto-teste` (se existir) ou um teste novo de forma do JSON, sem IFC do PO.
## Arquivos permitidos
`prototypes/viewport_qrhi/medir.py`; no máximo um teste novo em `tests/`. **Proibido:** `processo_malhas.py`, `carregador.py`, testes de oráculo existentes, metas.
