| # | Pergunta | Resposta |
|---|----------|----------|
| 1 | Cabeçalhos de ifcparse/ifcgeom em `$PREFIX/include`? | SIM (`include/ifcparse` 28 arquivos, `include/ifcgeom` 27) |
| 2 | Biblioteca para ligar em `$PREFIX/lib`? | SIM, mas com nome novo da 0.9: `libifcopenshell.parse.so`, `libifcopenshell.geometry.so` (+ `.writer`, `.plugin`), não `libIfcParse`/`libIfcGeom`. Há também CMake config `lib/cmake/IfcOpenShell/IfcOpenShellConfig.cmake` |
| 3 | Compartilhada ou estática? | COMPARTILHADA (.so). Nenhum `.a` de ifc* existe |
| 4 | O módulo Python usa a mesma biblioteca? | SIM. `_ifcopenshell_wrapper*.so` tem NEEDED `libifcopenshell.parse.so.0.9`, `.geometry.so.0.9`, `.plugin.so.0.9` (RPATH `$ORIGIN/../../..`, resolve para `$PREFIX/lib`). O wrapper só tem símbolos `ifcopenshell::file` indefinidos (U), vindos da biblioteca; não embute cópia |

Observação: cabeçalhos da 0.9 usam o namespace `ifcopenshell::` (ex.: `ifcopenshell::file`, arquivo `ifcparse/file.h`), não `IfcParse::IfcFile`/`IfcFile.h`. Isso é relevante para o teste 5 (R1, T3/S04). O plano da seção 8 do ADR-005 (sem cabeçalhos) NÃO é necessário.

Comandos e saídas curtas:
```
ls $P/include | grep -i ifc                 -> ifcgeom  ifcparse
find $P -iname "libifc*"                    -> lib/libifcopenshell.{parse,geometry,geometry.writer,plugin}.so[.0.9[.0]]
find $P -name "*.a" -iname "*ifc*"          -> (vazio)
readelf -d _ifcopenshell_wrapper*.so | grep NEEDED -> libifcopenshell.geometry.so.0.9, libifcopenshell.parse.so.0.9, libifcopenshell.plugin.so.0.9
ldd _ifcopenshell_wrapper*.so | grep ifc    -> todos resolvem em $PREFIX/lib
nm -DC --defined-only libifcopenshell.parse.so | grep -c "ifcopenshell::file::"  -> 48
nm -DC --defined-only _ifcopenshell_wrapper*.so | grep -c "ifcopenshell::file::" -> 0 (usa a biblioteca)
```
